# Как участвовать в разработке

## Окружение

```bash
git clone https://github.com/1vank1n/yougile-cli
cd yougile-cli
uv sync --extra dev
```

Запуск из исходников: `uv run yougile --help`.

## Изоляция конфигурации: обязательна

**Любой ручной прогон CLI делается с `YOUGILE_CONFIG_DIR=$(mktemp -d)`.** Без него
команда пишет в настоящий `hosts.yml` и `config.yml` разработчика: `config set`
меняет его настройки, `auth login` — его ключи, `config clear-cache` — его кэш.
Так уже один раз в реальном `config.yml` появился `output: json`, которого никто
не задавал.

```bash
export YOUGILE_CONFIG_DIR=$(mktemp -d)   # один раз на сессию терминала
uv run yougile --help

YOUGILE_CONFIG_DIR=$(mktemp -d) uv run yougile config list   # или разово
```

Правило действует для всего, что запускает CLI: ручная проверка, скрипт,
демонстрация в issue, отладка в редакторе. Каталог `$(mktemp -d)` каждый раз новый —
переиспользовать `/tmp/yougile` не надо, иначе состояние протекает между прогонами.

Тесты то же самое обязаны соблюдать сами: **ни один тест не имеет права дотянуться
до реального конфига.** Это закреплено дважды.

- В `tests/conftest.py` есть autouse-предохранитель: если в окружении стоит
  `PYTEST_CURRENT_TEST`, а `YOUGILE_CONFIG_DIR` не указывает внутрь временного
  каталога, тест падает с внятным сообщением.
- Тот же предохранитель встроен в код: при `PYTEST_CURRENT_TEST` функция
  `config_dir()` требует `YOUGILE_CONFIG_DIR` и иначе поднимает ошибку.

Поэтому новый тест не должен ни вызывать `platformdirs`, ни собирать путь к
конфигу руками, ни подменять `HOME` — он берёт каталог из общей фикстуры.
Если тест упал с жалобой на `YOUGILE_CONFIG_DIR`, чинить надо тест, а не
предохранитель.

## Перед пул-реквестом

```bash
uv run ruff check --fix src tests
uv run ruff format src tests
uv run pytest -q
uv run mypy src
```

Все четыре команды должны проходить без замечаний. CI
(`.github/workflows/ci.yml`) проверяет то же самое, только в неправящем виде:
`ruff check src tests`, `ruff format --check src tests`, `pytest -q --cov` на
Python 3.11–3.13 под Linux и macOS, плюс `mypy src` отдельной задачей.

Тесты не ходят в сеть: HTTP замокан через `respx`, а конфигурация подменяется
временным каталогом через `YOUGILE_CONFIG_DIR`. Любой новый запрос к API должен
быть покрыт тестом. Каждый исправленный дефект закрывается тестом, который падает
до правки и проходит после неё.

## Правила

- Команды именуются в стиле GitHub CLI: `list`, `view`, `create`, `edit`, `delete`,
  `close`, `reopen`. Никаких `get` и `update`.
- Не выдумывайте эндпоинты и поля: источник истины — <https://ru.yougile.com/api-v2>.
- Тексты для пользователя — по-русски, идентификаторы и комментарии в коде — по-английски.
- Метавары — заглавными по-русски и одинаковые во всех модулях: `НАЗВАНИЕ`,
  `ЗАГОЛОВОК`, `ЗАДАЧА`, `ДОСКА`, `КОЛОНКА`, `ПРОЕКТ`, `ОТДЕЛ`, `ЧАТ`, `СТИКЕР`,
  `СОТРУДНИК`, `ИСПОЛНИТЕЛЬ`, `ПОЛЯ`, `ВЫРАЖЕНИЕ`, `ФАЙЛ`, `КАТАЛОГ`, `URL`, `ID`.
  Латинских метаваров быть не должно.
- У всех `create` название — позиционный аргумент `НАЗВАНИЕ`; флаг `--title`
  (для стикеров `--name`) остаётся синонимом для скриптов.
- Сообщения об ошибках пишутся целыми фразами с согласованным родом
  («Доска не найдена», «Проект не найден»), а не шаблоном с подстановкой названия.
- Код возврата `2` — только для разбора аргументов и нашей валидации до отправки
  запроса. Ответ сервера — это `4` для `401`/`403` и `1` для всего остального.
- Комментарии только там, где объясняют неочевидную логику API.
- Python 3.11+, `from __future__ import annotations`, полные аннотации типов,
  строка не длиннее 100 символов.
- `typer` поставляется с вендоренным `click` (`typer._click`) — не импортируйте
  `click` напрямую.
- Сообщения коммитов в формате [Conventional Commits](https://www.conventionalcommits.org/ru/).

## Документация

`docs/commands.md` — полный справочник по всем командам: аргументы, флаги,
метавары, значения по умолчанию и пример на каждую команду. Если вы добавили или
переименовали команду, аргумент или флаг, обновите справочник и сводную таблицу
в `README.md`: они должны точно совпадать с выводом `yougile … --help`.
Проверять — обходом дерева справки, не по памяти:

```bash
YOUGILE_CONFIG_DIR=$(mktemp -d) uv run yougile task attachments --help
```
