# 0006. Релиз выпускается как 0.2.0

## Контекст

Набор правок поверх 0.1.0 закрывает девять issues: очистка вывода, доступность перечня полей, упаковка, документация, а также смена кода возврата неоднозначного имени с `2` на `1` и удаление настройки `pager`.

## Решение

Версия релиза — `0.2.0`. Тег `v0.2.0` ставится и пушится агентом с разрешения пользователя, GitHub Release собирается по тегу.

## Почему

Patch (0.1.1) отвергнут: он обещает, что ничего не сломается, а набор меняет контракт дважды — скрипт, различавший `1` и `2`, теперь получает другой код, и `config set pager` стал ошибкой. Patch описал бы набор неверно и лишил бы читателя changelog единственного сигнала «прочти инструкцию по обновлению».

Мажорная 1.0.0 отвергнута: ломки уровня «переписать использование» нет, а `1.0.0` в этой экосистеме читается как обещание стабильного API, которого проект пока не даёт.

При нуле в мажоре minor — обычное место для несовместимых мелочей, поэтому именно он несёт здесь смысл «поведение изменилось, посмотри что».

## Последствия

Версия и тег опубликованы — отменить их нельзя, ошибку в номере можно только перекрыть следующим релизом. Сломанные контракты (код возврата, `pager`) выпущены под minor, значит те, кто закрепляет `~=0.1` или обновляется не читая changelog, узнают о них по упавшему скрипту — отсюда обязательный блок обновления в `CHANGELOG.md`. Обещание стабильного API отложено: на нём же держится право ломать контракты в следующих `0.x`.
