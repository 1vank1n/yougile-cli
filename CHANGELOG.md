## [0.2.1] — 2026-09-03

### Как обновиться

```bash
uv tool install --force yougile-cli
# pipx install --force yougile-cli   ·   pip install -U yougile-cli
```

Это первый релиз, доступный на PyPI: команды выше ставят пакет прямо оттуда,
без git-ссылки и без установленного git. Поведение самого CLI не менялось ни
на байт, ломающих изменений нет.

### Добавлено

- Пакет публикуется на PyPI — `pip install yougile-cli` и
  `uv tool install yougile-cli` работают без git-ссылки.
- Публикация автоматическая: релизный workflow по тегу `v*` собирает колесо и
  sdist, сверяет версию в колесе с тегом, проверяет метаданные дистрибутива,
  гоняет линтер, типы и тесты, создаёт GitHub-релиз и заливает те же
  артефакты на PyPI. Аутентификация — Trusted Publishing по OIDC, токена PyPI
  в репозитории нет.

### Исправлено

- Относительные ссылки в README заменены на абсолютные: PyPI разрешает
  ссылки описания относительно `pypi.org`, и без этого они вели бы в 404. В
  метаданные добавлена ссылка на changelog.

### Документация

- README предлагает установку из PyPI первой; git-ссылка осталась ниже как
  способ поставить неопубликованную версию с `main`. В CONTRIBUTING появился
  раздел «Релиз» с шагами выпуска и разовой настройкой на pypi.org.

## [0.2.0] — 2026-09-03

### Как обновиться

```bash
uv tool install --force yougile-cli
# pipx install --force yougile-cli   ·   pip install -U yougile-cli
```

Скриптам на 0.1.0: неоднозначное имя теперь завершается кодом `1`, а не `2`, а
настройка `pager` удалена — `yougile config set pager` стал ошибкой (старый
`config.yml` с ключом `pager` при этом читается по-прежнему).

### Безопасность

- Строки, пришедшие с сервера, больше не управляют терминалом: управляющие
  последовательности (`\x00`–`\x08`, `\x0b`–`\x1f`, `\x80`–`\x9f`) заменяются
  на `�`. Это касается вывода `table`, `csv` и `tsv` — то есть и экрана
  (описания задач, вложения, чек-листы, подзадачи, сообщения чатов, дерево
  досок, отделы, `status`, выбор компании в `auth login`), и файла с выгрузкой,
  который потом откроют в терминале. Форматы `json` и `yaml` не очищаются —
  они экранируют сами, и очистка потеряла бы данные. ([#1])

### Изменено

- Неоднозначное имя — когда под указанное название подходит несколько досок,
  проектов, чатов и так далее — завершается кодом `1` вместо `2`. Код `2`
  остался только за ошибками вызова: разбором аргументов и нашей валидацией
  до отправки запроса. ([#9])
- Настройка `pager` удалена: её нет в `config get|set|list`, переменная
  окружения `YOUGILE_PAGER` больше не читается, упоминаний в README и
  `docs/commands.md` не осталось. Старый `config.yml` с ключом `pager`
  читается без ошибки. ([#10])

### Добавлено

- `--json` без значения печатает перечень доступных полей без сети и без
  входа: список берётся из статической схемы ресурсов API (новый модуль
  `yougile_cli.fields`) и объединяется с полями фактических строк, поэтому
  перечень виден и на пустой выдаче. Команды, для которых подтверждённой схемы
  нет (`task subscribers list`, `chat typing`, `file upload|download`,
  `crm contact create|view`), ведут себя как прежде: без входа перечень полей
  у них по-прежнему недоступен — «Вход не выполнен» и код `4`. ([#3])
- Маркер PEP 561 `src/yougile_cli/py.typed` — аннотации пакета видны
  потребителям и проверяются реальной сборкой колеса. ([#7])
- В состав sdist добавлены `CHANGELOG.md`, `CONTRIBUTING.md` и `docs/`. ([#6])
- CI: задача `build` собирает колесо и sdist, сверяет их состав, ставит колесо
  в чистое окружение и прогоняет `yougile --version` и `yg --help`. Проверка
  вынесена в composite action `./.github/actions/build-and-verify` и
  переиспользуется релизом, который сверяет с ней тег. ([#4])

### Исправлено

- Версия пакета больше не дублируется: `pyproject.toml` объявляет
  `dynamic = ["version"]` и читает её из `src/yougile_cli/__init__.py`. ([#2])
- Документация описывает, куда уходит Bearer-токен: на хост авторизации и на
  парный веб-хост того же облака (`yougile.com` ↔ `ru.yougile.com`), но не на
  посторонние адреса; вложения с чужих хостов отбрасываются. ([#8])

## [0.1.0] — 2026-09-02

Первый публичный релиз консольного клиента YouGile REST API v2.

### Добавлено

- **114 команд** в эргономике GitHub CLI: форма `yougile <сущность> <действие>
  [цель] [флаги]`, глаголы `list`, `view`, `create`, `edit`, `delete`, `close`,
  `reopen`, `move`. Две точки входа: `yougile` и короткая `yg`.
- **Авторизация**: `auth login` (интерактивный мастер, вход по паролю или готовым
  ключом, `--with-token` для CI), `auth logout`, `auth status`, `auth token`,
  `auth switch`, `auth refresh` и реестр ключей `auth keys list|create|delete`.
  Ключи хранятся в `hosts.yml` с правами `0600`, файл пишется атомарно.
- **Сущности API**: `project` (вместе с `project role`), `board`, `column`,
  `task` (вместе с `task subscribers`), `user`, `department`, `sticker string`
  и `sticker sprint` (вместе с их состояниями), `chat` и `chat message`,
  `webhook`, `company`, `file`, `crm contact`.
- **`yougile file download URL`** — скачать вложение по ссылке или по пути вида
  `/user-data/<uuid>/<имя>`. Параметр `previews[]` вырезается, поэтому качается
  оригинал, а не превью 480×480 (`--preview` его сохраняет). Загрузка идёт
  потоком, `-o` принимает и имя файла, и существующий каталог, существующий файл
  не перезаписывается без `--force`.
- **`yougile task attachments ЗАДАЧА`** — вложения задачи из HTML описания
  (`<img src>`, `<a href>`) и из сообщений чата, включая служебную форму
  `/root/#file:<url-encoded путь>`. Колонки `ИСТОЧНИК`, `ИМЯ`, `ТИП`, `URL`,
  фильтр `--source описание|чат|все`, массовое скачивание `--download --dir`.
- **Разрешение имён**: доски, колонки, проекты, отделы, стикеры, чаты и
  сотрудников можно указывать названием, e-mail или ссылкой вместо ID;
  `@me` подставляет текущего сотрудника.
- **Ссылки из интерфейса и коды задач**: `task view`, `edit`, `close`, `comment`,
  `move`, `delete`, `chat messages`, `browse` и остальные команды принимают
  `ILS-343`, `https://ru.yougile.com/team/…/#ILS-343`,
  `https://ru.yougile.com/board/<uuid>#ILS-343`, `…#sticker-<uuid>`,
  `…#chat-<uuid>`, `…/api-v2/tasks/<uuid>` и голый UUID. Код задачи
  (`idTaskProject`) разрешается полным обходом `/api-v2/task-list`; карта
  `КОД → id` кэшируется в `<каталог конфигурации>/cache/tasks-<хост>.json`
  с правами `0600` и сроком жизни 24 часа, чистится `config clear-cache`.
- **Вывод**: глобальный `-o/--output` с форматами `table`, `json`, `yaml`, `csv`,
  `tsv`, `ids`; gh-совместимые `--json ПОЛЯ` (без значения — список полей),
  `-q/--jq`, `-L/--limit` (`0` — все страницы) и `--full-ids`.
- **`yougile api`** — произвольный запрос к любому эндпоинту: `-X`, `-f`, `-F`,
  `-H`, `--input`, `--paginate`, `--include`, `--silent`, `--verbose`.
- **Локальные удобства**: `config get|set|list|clear-cache`, алиасы
  `alias list|set|delete` с подстановкой `$1`…`$N` и `$@`, `status`, `browse`,
  `version`, автодополнение `completion` и `completion install`.
- **HTTP-клиент**: ограничитель на 50 запросов в минуту, автоповторы на `429`
  и `5xx` с учётом `Retry-After`, автоматическая пагинация по `paging.offset`.
- Документация: [README](README.md) и полный справочник
  [docs/commands.md](docs/commands.md).

### Поведение команд

- У всех `create` название — **позиционный аргумент** `НАЗВАНИЕ`; `--title`
  (для стикеров `--name`) остаётся синонимом для скриптов. Если заданы оба и они
  различаются — ошибка с кодом `2`. У `task create` позиционный `ЗАГОЛОВОК`
  необязателен: заголовок может прийти из `--editor`.
- `task move` принимает колонку позиционно и флагом `--column`; `task assign` и
  `task unassign` — исполнителей позиционно и повторяемым `--assignee`.
- Метавары приведены к единому виду: заглавными по-русски (`НАЗВАНИЕ`, `ЗАДАЧА`,
  `ДОСКА`, `КОЛОНКА`, `ПРОЕКТ`, `ОТДЕЛ`, `ЧАТ`, `СТИКЕР`, `СОТРУДНИК`,
  `ИСПОЛНИТЕЛЬ`, `ПОЛЯ`, `ВЫРАЖЕНИЕ`, `ФАЙЛ`, `КАТАЛОГ`, `URL`, `ID`).
  Латинских метаваров не осталось.
- `task view` в табличном режиме показывает описание читаемым текстом: абзацы
  переносами строк, `<li>` маркерами, `<br>` переносом, сущности раскодированы
  (`html.parser` из стандартной библиотеки, без новых зависимостей). Исходный
  HTML — под флагом `--raw-description`. Появилась секция `ВЛОЖЕНИЯ`.
- `chat messages` в табличном режиме превращает служебную форму
  `/root/#file:…` в читаемое имя файла со ссылкой и чистит текст от HTML;
  в режиме `json` тело сообщения отдаётся как есть.
- Пустой список больше не выглядит поломкой: в режиме `table` в **stderr**
  печатается тусклая строка `Ничего не найдено.`, stdout остаётся пустым,
  код возврата — `0`. В `json`, `yaml`, `csv`, `tsv` и `ids` поведение прежнее.
- Сообщения об ошибках согласованы по роду и числу: «Доска не найдена»,
  «Проект не найден», «Найдено несколько досок с именем «X»» — вместо шаблона
  с подстановкой названия сущности.
- Идентификаторы в табличном режиме сокращаются единообразно: под сокращение
  попадает любое значение-UUID, а не перечень имён полей, поэтому `createdBy`
  и элементы `assigned` режутся так же, как `id` и `*Id`. Снимается
  глобальным `--full-ids`.
- **Коды возврата как у `gh`**: `0`, `1`, `2`, `4`, `130`. Код `2` — только для
  разбора аргументов и нашей валидации до отправки запроса; ответ сервера
  `401`/`403` даёт `4`, любой другой отказ (`400`, `404`, `409`, `422`, `429`,
  `5xx`) — `1`. Сообщения об ошибках печатаются с подсказкой на второй строке.
- `api --paginate` после склейки страниц пересобирает конверт как
  `{"count": N, "limit": N, "offset": 0, "next": false}`, где `N` — фактическая
  длина `content`, а не `limit` последней страницы.

### Безопасность

- Реальный конфиг пользователя защищён от тестов и прогонов CLI: при
  `PYTEST_CURRENT_TEST` в окружении `config_dir()` требует `YOUGILE_CONFIG_DIR`,
  а autouse-фикстура в `tests/conftest.py` роняет тест, если каталог не указан
  или лежит вне временного. Ручные прогоны CLI делаются с
  `YOUGILE_CONFIG_DIR=$(mktemp -d)` — правило описано в [CONTRIBUTING](CONTRIBUTING.md).
